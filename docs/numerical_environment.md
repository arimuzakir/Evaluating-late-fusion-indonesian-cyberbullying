# Numerical environment, BLAS determinism, and GPU runtime reconciliation

## 1. CPU frozen-feature BLAS determinism (`v1.1.2` / `v1.2.0`)

The `v1.1.1` frozen-feature repeated-partition tables (`results/generalization/REPEATED_SPLIT_METRICS.csv` and `results/generalization/REPEATED_SPLIT_SUMMARY.csv`) agree with numerical recomputation using a single BLAS thread (`threadpoolctl.threadpool_limits(limits=1)`). Multi-threaded linear algebra in some environments changes the tie-breaking order of near-equal floating-point probabilities and yielded tiny ROC-AUC/AP differences in three text-probe rows (up to `0.0005965` ROC-AUC and `0.0001427` AP), while leaving binary predictions, confusion matrices, Macro F1, and primary focal effects unchanged. On Apple Silicon ARM64 (`Accelerate`) versus x86_64 (`OpenBLAS`), `liblinear` coordinate descent exhibits a maximum probability difference of `0.00128` on 5 out of 15,640 rows while producing identical binary predictions (`15,640/15,640`) and identical Macro F1 (`< 1e-8`).

The archived `REPEATED_SPLIT_*` files **have not been modified**, and their SHA-256 hashes match `v1.1.1`.

## 2. GPU runtime comparison and neural-head sensitivity reconciliation (`R1.3`)

In the V4 reviewer revision (`results/video/revision_20261108/head_sensitivity/HEAD_BASELINE_RECONCILIATION.csv`, `results/video/revision_20261108/head_sensitivity/HEAD_REPLAY_DIAGNOSTICS.csv`, `docs/provenance/revision_20261108/TRAINING_ENVIRONMENT_COMPARISON.csv`, `docs/provenance/revision_20261108/TRAINING_EXECUTION_ENVIRONMENT.json`, and `configs/revision_20261108/NUMERICAL_RUNTIME_LIMITS.json`), the 48-fit 2×3×2 factorial neural-head sensitivity grid (`concat_mlp` and `healnet` / `healnet_adapted_2024` across `epochs ∈ {15, 30, 60}` and `weight_decay ∈ {0.01, 0.1}`, 4 folds at seed `42`, `learning_rate = 0.001`, `batch_size = 64`) was executed on an **NVIDIA L4** GPU (`cuda_runtime = 13.0`, `python = 3.13.16 (main, Oct  1 2026, 15:40:24) [GCC 13.3.0]`, `pandas = 2.2.3`, `scikit-learn = 1.6.1`, `transformers = 4.57.1`, `einops = 0.8.1`, `emoji = 2.14.1`), matching the GPU model and Python/CUDA versions recorded in the primary `GoldAdjudicated v1.1` run (`results/video/gold_adjudicated_v1.1/VIDEO_OOF_PREDICTIONS.csv`) and producing identical fold `StandardScaler` bytes (`scaler_bytes_equal = True` across all 4 folds).

However, the two runs executed in separate software environments (`numpy 2.1.3` vs `2.4.6`, `torch 2.11.0+cu130` vs `2.14.1+cu130`, `torchvision 0.26.0+cu130` vs `0.29.1+cu130`, `Linux-6.6.122+-x86_64-with-glibc2.39` vs `Linux-6.6.159+-x86_64-with-glibc2.39`), and the original Gold notebook explicitly set `torch.set_float32_matmul_precision('high')` whereas that call was `NOT_SET_IN_ARCHIVED_NOTEBOOK` in the sensitivity notebook. At the baseline setting (`epochs = 30, weight_decay = 0.01`), pooled OOF Macro F1 differs slightly between the frozen primary run and the sensitivity replay:
- `concat_mlp`: **`0.507951623552652`** (frozen primary Table 3) vs **`0.5017144487753278`** (`concat_mlp_e30_wd0.01` sensitivity replay, `delta = -0.006237174777324217`)
- `healnet_adapted_2024`: **`0.5098265619167537`** (frozen primary Table 3) vs **`0.4938767980947205`** (`healnet_e30_wd0.01` sensitivity replay, `delta = -0.01594976382203317`)

Because multiple runtime and library factors differed simultaneously, **causal attribution of the replay discrepancy remains unresolved**. Primary Table 3 retains the frozen `v1.1` predictions unchanged; the 12 pooled sensitivity configurations (`concat_mlp`: `0.4876617530360183` [`concat_mlp_e60_wd0.1`] to `0.5054619174213288` [`concat_mlp_e30_wd0.1`]; `healnet`: `0.48995107844566277` [`healnet_e60_wd0.01`] to `0.5094701632707828` [`healnet_e15_wd0.01`] in `results/video/revision_20261108/head_sensitivity/HEAD_SENSITIVITY_POOLED.csv`) are evaluated across their consistent sensitivity runtime (`python scripts/validation/verify_revision.py --root .`).
