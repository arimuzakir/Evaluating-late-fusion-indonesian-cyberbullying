# Methods and reproducibility

## 1. Cohorts, alignment exclusions, and five-role evaluation design (`R1.1`, `R1.4`, `R2.4`)

The frozen `v1.1-GoldAdjudicated` label inventory contains 13,307 observations: 8,906 standalone text comments and 4,401 ten-second video windows (segmented with a 10 s window and 3 s stride from 233 source videos). The multimodal alignment filter retains **3,951** video windows across **214** linked source groups (`2,326` positive, `1,625` negative). The remaining **450** segmented windows (`280` positive, `170` negative; `62.22%` positive vs `58.87%` in the 3,951 retained windows) fail the duplicate/content-match alignment audit recorded in `results/statistics/revision_20261108/exclusions/EXCLUSION_REASON_PLATFORM_CLASS.csv` and `EXCLUSION_SOURCE_CHARACTERISTICS.csv`:
- `frame_identity_match = false` only: **187** windows
- `frame_identity_match = false` and `stt_content_match = false`: **220** windows
- `ocr_content_match = false` only: **35** windows
- `frame_identity_match = false` and `ocr_content_match = false`: **5** windows
- `frame_identity_match = false`, `ocr_content_match = false`, and `stt_content_match = false`: **3** windows

No model accuracy is imputed for these 450 excluded windows. The high-agreement standalone-comment benchmark retains **8,196** comments (`1,226` held-out test across `865` source groups). The two tracks are evaluated independently and are never pooled into a single accuracy metric.

In the primary video evaluation (`results/video/gold_adjudicated_v1.1/`), source groups are partitioned into four source-disjoint outer folds (`fold 0..3`) and five mutually disjoint roles within each fold (`fit`, `early_stop`, `meta_fit`, `calibration`, `test`), repeated across three training seeds (`42, 2026, 2027`). Per-fold role counts (`windows`, `groups`, `negative`, `positive`, and `text_windows`/`text_groups` where `ocr_ok == 1` or `stt_ok == 1`) are archived in `results/video/revision_20261108/roles/ROLE_COUNTS.csv`, and the role isolation rules for all **23 configurations** (21 primary models plus 2 seed-42 probability controls) are archived in `results/video/revision_20261108/roles/MODEL_ROLE_RULES.csv` and `configs/revision_20261108/ORIGINAL_ROLE_ALLOCATION_RULES.json`.

When both OCR and STT outputs are empty (`685` of `3,951` aligned windows: `423` positive, `262` negative), extracted-text branches receive a zero text feature vector and emit the neutral fallback probability `p = 0.5`. Because the positivity decision rule is **`probability >= threshold`** (`p >= τ*`), `p = 0.5` yields `all_positive` whenever the calibration-selected fold threshold satisfies `τ* <= 0.5` and `all_negative` whenever `τ* > 0.5` (`results/statistics/revision_20261108/fallback/TEXT_FALLBACK_DECISIONS.csv`). Exact per-fold and pooled fallback confusion matrices (`tn, fp, fn, tp`, `macro_f1`) across all 21 models × 3 seeds and the 2 seed-42 probability controls are archived in `NO_TEXT_FALLBACK.csv` and `CALIBRATION_CONTROL_FALLBACK.csv`.

## 2. Primary inference, estimand hierarchy, and retrospective MDE (`R1.7`, `R1.8`, `R2.6`)

Primary video scores in Table 3 (`results/statistics/revision_20261108/main_result_checks/TABLE3_RECOMPUTED.csv` and `THREE_SEED_RECOMPUTED.csv`) are computed on **pooled out-of-fold (`OOF`) predictions** across all 3,951 aligned windows (not an unweighted mean across outer folds). Paired differences are computed from unrounded pooled OOF scores (`docs/provenance/revision_20261108/ROUNDING_AND_MDE.json`):
- **Focal seed-42 contrast (`results/statistics/FOCAL_FOUR_100000.csv`)**: Resampling or sign-flipping all windows within each of the 214 source groups together (`100,000` replicates) yields `text = 0.5703396012843986`, `equal_vat = 0.5669772833605011`, `delta_macro_f1 = −0.0033623179238975`, 95% source-clustered bootstrap CI **`[−0.0178765858028778, +0.0115901332544028]`**, two-sided paired sign-flip permutation **`p = 0.6607533924660753`**, and four-contrast Holm-adjusted **`p_holm_four = 0.6607533924660753`**. Across all four focal contrasts (`equal_vat vs text`, `equal_va vs visual`, `vat_coverage vs vat_lr`, and `vat_coverage vs healnet_adapted_2024`), `p_holm_four` spans `0.594456` to `0.660753`.
- **Standalone comment multiplicity family (`docs/provenance/revision_20261108/COMMENT_MULTIPLICITY_FAMILY.csv`)**: Held-out comment inference (`1,226` comments across `865` source groups, `2,000` replicates at seed `42`) applies Holm step-down adjustment across the four baseline contrasts comparing `equal_text_ensemble` against `indobertweet`, `indobert`, `mdeberta_v3`, and `tfidf_lr`.
- **Retrospective minimum detectable effect (`docs/provenance/revision_20261108/ROUNDING_AND_MDE.json`)**: Using the empirical source-clustered bootstrap standard error (`bootstrap_se = 0.0075124837897468` from `100,000` replicates), the unadjusted two-sided (`α = 0.05`) 80%-power normal-approximation MDE `(norm.ppf(0.975) + norm.ppf(0.8)) * bootstrap_se` is **`0.021046863536667928`** Macro F1. This quantity is a retrospective conditional normal-approximation sensitivity diagnostic; it is not Holm-adjusted, prospective power, or formal equivalence proof.
- **Probability estimand hierarchy (`docs/provenance/revision_20261108/PROBABILITY_ESTIMAND.json`)**: Window-weighted Brier score and 10-bin positive-class ECE (`w_i = 1`, where every evaluated 10 s window contributes equally) are designated as the primary probability-quality estimand, while source-weighted Brier score and ECE (`w_i = 1 / n_{g(i)}`, where each of the 214 source groups contributes equally) are reported as a cluster-size sensitivity analysis (`results/statistics/revision_20261108/probability/TABLE6_PROBABILITY_METRICS.csv`, `BRIER_PAIRED_INTERVALS.csv`, and `RELIABILITY_BINS.csv`). Because the original protocol locks did not specify window- versus source-weighted priority for probability calibration, this hierarchy is explicitly documented as a revision-time reporting decision.

## 3. Reviewer-requested V4 sensitivity and control analyses

1. **Two additional 5-role main-pipeline source-group allocations (`R2.5`)**:
   To evaluate sensitivity to the source-group allocation on the fine-tuned main pipeline, two new four-fold, five-role (`fit`, `early_stop`, `meta_fit`, `calibration`, `test`) source-disjoint allocations were generated without inspecting prediction scores (`results/video/revision_20261108/source_partitions/PARTITION_SEED_LEDGER.csv`, `PARTITION_1042_ROLES.csv`, `PARTITION_2042_ROLES.csv`), and the focal **`text` vs `equal_vat`** branches (`indobenchmark/indobert-base-p2`, `EfficientNet-B0`, and `waveform16_v1` logistic regression) were trained from scratch at `training_seed = 42` (`REPARTITION_EFFECTS.csv` and `REPARTITION_PREDICTIONS.csv`; other auxiliary models and post-hoc controls were not retrained on these partitions):
   - **Partition `1042`** (`search_start_seed = 1042`, `effective_outer_seed = 1042`, `training_seed = 42`): `text_f1 = 0.5322441613114784`, `equal_vat_f1 = 0.547547707084874`, `delta = +0.015303545773395544`, 95% source-clustered bootstrap CI **`[−0.0013907197934134488, +0.032653003054556234]`**.
   - **Partition `2042`** (`search_start_seed = 2042`, `effective_outer_seed = 2044`—the first candidate seed from `2042` satisfying fold window/class/platform constraints—with `training_seed = 42`): `text_f1 = 0.5469555003724585`, `equal_vat_f1 = 0.541611762016599`, `delta = −0.005343738355859551`, 95% source-clustered bootstrap CI **`[−0.02085725995059201, +0.01140696636205858]`**.
   - **Bootstrap group-ordering provenance (`Item 8`)**: During `INITIAL_RUN`, `repartition()` computed `paired_ci()` on un-pseudonymized `group_id` strings before `save()` replaced `group_id` with `src_<16hex>` SHA-256 pseudonyms in `REPARTITION_PREDICTIONS.csv`. Because `master_id` (`MV_000001..MV_004386`) was assigned in alphabetical order of the original un-pseudonymized source identifiers, ordering unique `group_id`s by their first appearance in `master_id` order (`pd.unique(d.sort_values('master_id').group_id)`) in `scripts/analysis/reproduce_revision.py` recovers the exact 214-group pre-pseudonymization ordering and reproduces `REPARTITION_EFFECTS.csv` (`text_f1`, `equal_vat_f1`, `delta`, `ci_low`, `ci_high`) to **`0.0` (`atol = 1e-12`)**. If the 214 groups are instead ordered lexicographically by their pseudonymized `src_<16hex>` strings (`np.unique(d.group_id)`), the multinomial bootstrap permutation shifts the 95% CI quantiles by at most `4.42e-4` (`[−0.0015131384766076195, +0.032329495427405756]` for `1042`; `[−0.02062388609164806, +0.010964716587871032]` for `2042`), while point estimates are identical. Both intervals are verified deterministically at `atol = 1e-12` in `scripts/validation/verify_revision.py`.

2. **Neural fusion head 2×3×2 sensitivity and runtime reconciliation (`R1.3`)**:
   Holding the cached seed-42 branch encoder outputs (`1280D` visual, `16D` acoustic, `768D` text) and `meta_fit` `StandardScaler` bytes fixed, **two neural fusion heads**—`concat_mlp` (`dimensions [2064, 128, 32, 2]`, dropout `0.2`) and `healnet` (`healnet_adapted_2024`, local vector-token adaptation with `tokens_per_modality = 1`, `depth = 2`, `l_c = 16`, `l_d = 64`, `x_heads = 4`, `l_heads = 4`, `fourier_encode_data = False`)—were trained on `meta_fit` across **epochs `{15, 30, 60}`** and **weight decay `{0.01, 0.1}`** (`learning_rate = 0.001`, `batch_size = 64`, `seed = 42`, `4` outer folds = `12` pooled configurations / `48` fold fits; see `configs/revision_20261108/FUSION_HEAD_CONFIGURATION.json`, `PROTOCOL_LOCK.json`, and `results/video/revision_20261108/head_sensitivity/HEAD_SENSITIVITY_POOLED.csv`):
   - `concat_mlp` pooled OOF Macro F1 ranges from **`0.4876617530360183`** (`concat_mlp_e60_wd0.1`) to **`0.5054619174213288`** (`concat_mlp_e15_wd0.01`).
   - `healnet` pooled OOF Macro F1 ranges from **`0.48995107844566277`** (`healnet_e15_wd0.01`) to **`0.5094701632707828`** (`healnet_e60_wd0.1`).
   - **Baseline replay reconciliation (`HEAD_BASELINE_RECONCILIATION.csv`, `HEAD_REPLAY_DIAGNOSTICS.csv`, `TRAINING_ENVIRONMENT_COMPARISON.csv`, `configs/revision_20261108/NUMERICAL_RUNTIME_LIMITS.json`)**: Both the original `GoldAdjudicated v1.1` run and the sensitivity run recorded an **NVIDIA L4** GPU and identical fold scaler SHA-256 digests (`scaler_bytes_equal = True` across all 4 folds), but executed under different software stacks (`numpy 2.1.3` vs `2.4.6`, `torch 2.11.0+cu130` vs `2.14.1+cu130`, `torchvision 0.26.0+cu130` vs `0.29.1+cu130`, Linux `6.6.122+` vs `6.6.113+`), and `torch.set_float32_matmul_precision('high')` was set in the original Gold notebook whereas it was not set in the archived sensitivity notebook. At the baseline setting (`epochs = 30, weight_decay = 0.01`), pooled Macro F1 is `0.507951623552652` (original Table 3) vs `0.5017144487753278` (sensitivity replay, `Δ = −0.006237174777324217`) for `concat_mlp`, and `0.5098265619167537` (original Table 3) vs `0.4938767980947205` (sensitivity replay, `Δ = −0.01594976382203317`) for `healnet_adapted_2024`. Because multiple runtime factors changed simultaneously, **causal attribution of the replay discrepancy remains unresolved**. Original Table 3 scores are retained unchanged.
